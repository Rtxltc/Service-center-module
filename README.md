# Service-center-module

## Service Calls

The admin portal includes a Service Calls module backed by the existing Express API and PostgreSQL/Supabase database. Before starting the updated backend, apply the additive migration in `backend/migrations/001_service_calls.sql` to the existing database:

- PostgreSQL: `psql "$DATABASE_URL" -f backend/migrations/001_service_calls.sql`
- Supabase: run the SQL file in the project's SQL Editor.

The migration creates the service-call and SOIN audit tables, indexes, the 47-hour deadline trigger, and the atomic SOIN update function. It does not modify existing repair, income, expense, or contact records. Do not apply it to a different database than the one configured for the backend.

For Supabase deployments, configure `SUPABASE_SERVICE_ROLE_KEY` (or `SUPABASE_KEY`) as the server-only service-role key. Row-level security is enabled on the new service-call tables without public policies, so the publishable/anon key cannot read or modify service calls directly. Never put the service-role key in the frontend.

Service-call API endpoints are protected by the existing `x-admin-password` admin authentication:

- `GET/POST /api/service-calls`
- `GET/PUT /api/service-calls/:id`
- `PATCH /api/service-calls/:id/soin`
- `GET /api/service-calls/:id/history`
- `GET /api/service-calls/dashboard`
- `GET /api/service-calls/export`

The Excel export is generated by the backend and downloads all records matching the selected filters, across all pages. Service-call payment amounts are tracked separately and are not posted to the existing income ledger.
